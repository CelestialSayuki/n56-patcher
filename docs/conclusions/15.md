# N56 · iOS 15.8.8

15.8.8（19H422）是 iPhone 6 Plus 的第三个系统候选，装在独立的 System15 / Data15 卷上，和 iOS 12.5.8（16H88，原机）共用一个 APFS 容器。内核、系统镜像和 rootfs 底包取自 J96（iPad mini 4），同版本驱动和 iPhone 资源取自 N66（6s Plus），原生硬件材料（SEP 固件、Mav10 基带、B1 Wi-Fi 固件、校准与机型文件）仍来自 N56 原机。

**当前进展（2026-11-19）：s4/s5 已从空卷全量重装，Data15 加密，已进用户态并完成激活；音频、相机、蓝牙、基带已上机验证。** 各项状态见“现状”。

## 前提

- 设备刷回 iOS 12.5.8（16H88）。
- `ipsw/` 下放三个 IPSW，文件名不变：

  ```text
  ipsw/iPhone_5.5_12.5.8_16H88_Restore.ipsw            # N56
  ipsw/iPhone_5.5_15.8.8_19H422_Restore.ipsw           # N66
  ipsw/iPad_64bit_TouchID_15.8.8_19H422_Restore.ipsw   # J96
  ```

- rootless/rootful 用到的上游包（binpack、procursus bootstrap、Sileo 等）全部固定 SHA256。用 `python3 -m patches.ios15.impl.rootfs.rootless_bootstrap` 一次性下载到 `ipsw/cache/ios15-rootless/`，构建过程本身不联网。
- 环境：Python 3.10 及以上，用 `tools/bootstrap.sh` 准备，Intel 和 Apple Silicon 宿主都可以。

## 构建

离线构建不访问手机。卷号只是构建参数，不代表手机上已经存在这两个分区：

```sh
python3 n56patcher.py build --target n56-ios15 --system 6 --data 7 \
  --jailbreak-mode rootless --data-protection encrypted \
  --workdir build/n56-ios15-19H422/<本次目录>
```

target 默认 features 就是完整硬件集（含 `audio`、`palera1n`、`ssv`、`paleinfo`、`rootless`）。Data 保护默认仍为 `none`，当前上机配置是加密 Data15，须显式加 `--data-protection encrypted`。

构建输入只有这几类：`ipsw/` 的 IPSW、`ipsw/cache/` 的 rootfs DMG 和下载缓存、`ipsw/cache/derived/ios15-19H422/`（由 `patches/ios15/inputs.py` 从 IPSW 生成）、`donors/`、`state/`（IM4M、donor 快照），以及 Context 对 DMG 的只读挂载。`build/` 只用来放输出。build 签进 TC 的文件（`rootless-final/`、`rootful-final/`、`companion/` 等）留在同一个 workdir 里，install 时原样部署。

## 安装

先用 dry-run 演练，此步不接触手机：

```sh
python3 n56patcher.py install --target n56-ios15 --dry-run --system <N> --data <M> --workdir <目录>
```

真实安装走同一个 `install` 阶段，功能选择须与 build 时一致。写入 System 之前，`system_policy.before_system_write` 会检查以下各项：

- 五件 IMG4 的 SHA 与当前 IM4M 一致；
- 功能选择与 build 时一致；
- KPF → SSV 证明链完整；
- System 未 seal、没有 snapshot。

已有 seal 或 snapshot 时直接拒绝，不会自动删除或重命名。

通过宗卷（GUI 或 `n56patcher.py slots install 15`）安装时，工作目录固定为 `build/slots/15`，装完记入 `state/volumes.json`。之后开机：设备进 DFU，GUI 里启动 15，或执行 `python3 n56patcher.py boot --slot 15`。

设备验收按这个顺序：

1. 启动：系统版本 15.8.8 / 19H422，能进 SpringBoard，屏幕、触摸正常。
2. 卷：根是所选的 System15（只读）；stage0 将 Data15 的 `/private/var` 更新为 `suid,nodev` 并由 runtime 复查，原 12 卷保留。
3. rootless：`/var/jb` 指向 Data15 上的 bootstrap，sudo、SSH、Sileo `giveMeRoot` 均要求实际挂载不含 `nosuid`。
4. 激活与网络：Wi-Fi、FairPlay、激活、基带和 SIM 状态。
5. 硬件：充电、温度、震动、蓝牙、相机、播放与录音、耳机。
6. 稳定性：息屏后唤醒；再做一次 tethered 启动。

出现失败时，先保留串口日志和 panic 信息，不要反复刷写或重建 systembag。

## 空间

- J96 19H422 的 dyld cache 被拆成主文件、`.1` 到 `.5` 和 `.symbols`，共 2,324 个镜像。`core/dyld_cache.py` 是只读读取层，按 VM 地址定位到子文件。
- 系统卷沿用 14 的 decmpfs 透明压缩写入。
- System15 的实际占用还没在设备上量过。安装前按 14 的方法先用 `fsck_apfs` 估算剩余空间。

## 关键适配（相对 14）

- **卷**：独立的 System15 / Data15。target 默认不加密，当前设备用加密 Data15（s5）。
- **音频**：入口和 14 相同（N56 原生 CS42L67），但 15 的 ABI 差异更大：先在当前 KC 的空余 padding 里暂存原生代码，再闭合布局、继承关系和私有入口，最后把七个剩余入口接到 15 的原生函数上，并发布 personality。12 → 14 → 15 的对照事实固定在 `audio-abi-profile.json` / `audio-final-profile.json`；其中 iOS 14 参照内核来自 `ipsw/cache/derived/ios14-18H17/j96/kernel.raw`，单测核对它的哈希。
- **SEP**：沿用旧协议桥（固定端点、SKS v0、SCRD、SSE）。现代 media/file 包装统一转换到 v0，SKS61 只接受空 cookie。SKS15 重封装与 SKS16 新密钥生成的请求 flags 对齐 13/14：`0x1c → 0xc`；重封装的空附加输出保持 `0`。新密钥的盘上包装输出接到 v2 第四组，对应 13 的第三组。
- **Touch ID**：Mesa 收发转换和 14 HEAD 一致；SBIO 只由 `kc.touchid` 发布。
- **运动、基带、蓝牙、温控**：在 15 的 chained fixups 和新分组上重新定位。各项 VA 编辑合并后统一规划，只调用一次 `plan_edits`。
- **激活 UIK**：15 的 `mobileactivationd` 让 SEP 维护系统 UIK（`osko`，selector 43 → SKS34），12 的 SEP 不支持，返回 -12。`rootfs.activation_legacy_sep` 把 `copy_uik` 和 UIK 的 bump/commit 接到 `/usr/lib/n56-mobileactivation.dylib`，按 14 的方式生成 SEA 引用密钥（`kSecAttrAccessibleAlwaysThisDeviceOnlyPrivate` + PrivateKeyUsage），引用存进 mobileactivationd 系统容器的 `Library/uik`。`copy_uik` 返回 +1 引用，不能 autorelease。
- **companion**：从 N66 cache 派生 69 个库，当前派生版本为 7。compact 扫 `__const`/`__data` 的 32 位相对指针时，目标落在新建的 `__EXTRA_OBJC` 一律跳过：rebuild 把该段紧贴最后一个数据段放置，VWT flags 等整数会"指"进去被误平移（IsNonInline/IsNonPOD 丢失 → existential 内联溢出、堆损坏，表现为健康各处随机崩溃）。v6 的 count 8 位截断是这个的下游症状，已删。

## 已知问题

- 单元测试：`python3 -B -m unittest discover -s patches/ios15 -t . -p 'test_*.py'`。需要的 KC 中间产物和 rootfs 挂载都由 `fixtures.py` 现场生成，缺 derived 输入或 DMG 时跳过并写明缺哪份 `ipsw/` 文件。
- 13/14 仍各自使用自己那份 companion 工具（`patches/ios13/impl/rootfs/health_toolchain`、`patches/ios14/impl/rootfs/companion`），尚未切换到 `patches/shared` 的副本；`patches/shared/impl/rootfs/thermal/macho.py`（14 使用）仍然 import 14 的 toolchain。
- core 的 `test_host` 有 2 项失败，问题在 `core/host.py` 的候选工具选择逻辑，与 iOS 15 无关。
