# N56 · iOS 14.8

14.8（18H17）作为 iPhone 6 Plus 的第二系统，装在独立的 System14 / Data14 卷上，和 iOS 12.5.8（SystemA）共用一个 APFS 容器。内核和系统镜像来自 J96（iPad mini 4），同版本驱动、设备树节点和 iPhone 专属资源来自 N66（6s Plus），原生硬件材料（SEP 固件、基带、校准数据、机型文件）从本机 SystemA 读取。

截至第 94 轮（2026-11-14），从刷机后的干净设备执行一次 `all` 可以装到当前阶段：开机进系统、主要硬件可用、checkra1n 越狱、Cydia 和 USB SSH。当前代码离线构建出来的五个启动镜像和 boot94 实机启动包逐字节一致。写入方式改成了保留透明压缩（见“空间”一节），这一点还要在重刷后跑一次完整的 `all` 来验证。

## 刷机后一次跑通

### 前提

- 设备刷回 iOS 12.5.8（16H88）。刷机后 APTicket 会变，旧的 `state/IM4M.bin` 和旧启动包都会失效，`all` 会自动重新提取。
- `ipsw/` 下放好三个 IPSW，文件名不变：

  ```text
  ipsw/iPhone_5.5_12.5.8_16H88_Restore.ipsw           # N56
  ipsw/iPhone_5.5_14.8_18H17_Restore.ipsw             # N66
  ipsw/iPad_64bit_TouchID_14.8_18H17_Restore.ipsw     # J96
  ```

- 环境按 README 准备（Xcode、`tools/setup.py`、SSH ramdisk）。Cydia 底包第一次用时会从 `assets.checkra.in` 下载到 `ipsw/cache/cydia/`，之后复用。

### 命令

设备进 DFU，然后：

```sh
sudo python3 n56patcher.py all --target n56-ios14
# 或者网页界面：sudo python3 gui.py，目标选 n56-ios14，阶段选“端到端”
```

Data14 默认加密（`--data-protection none` 可改为不加密）。第 94 轮及以前装的都是 `none`，加密模式在 14.8 上从第 95 轮开始验证：开机要靠 SEP 的 SKS 服务解锁数据卷，如果卡在开机，先改回 `none` 排除这个因素。

流程：缺文件时解密 iBSS/iBEC → 进 ramdisk（端口 2223）→ 重提 IM4M → 建 System14/Data14 卷 → 写入 J96 系统镜像 → 打全部 rootfs 补丁（含越狱和 Cydia）→ 初始化 Data14、设置卷 role → 构建五件套 → 发送启动链。干净的 12.5.8 上卷号通常是 s4/s5，实际卷号记在工作目录的 `layout.json` 里，之后的构建会自动读取。

### 首次开机

- 开机后约 30 秒，`com.n56.checkra1n` 的初始化脚本会把根分区重挂为可写，然后运行 `firmware.sh` 和 `dpkg --configure -a`，并给 Cydia、checkra1n Loader 注册图标。日志在 `/var/log/n56-cydia.log` 和 `/var/log/n56-checkra1n.log`。
- USB SSH：在主机上执行 `iproxy 2244:44`，再 `ssh -p 2244 root@127.0.0.1`，密码 `alpine`。设备上的工具在 `/binpack`，用之前先 `export PATH=$PATH:/binpack/usr/bin:/binpack/bin:/binpack/usr/sbin`。
- 之后再开机：设备进 DFU，执行 `python3 n56patcher.py boot --target n56-ios14`。如果启动包是用非默认功能构建的，`boot` 时必须带上同样的 `--features`，否则会按不同的选择重新构建。

## 空间

16 GB 机型的容器只有 3,906,239 个 4 KiB 块（14.9 GiB）。第 94 轮实测 System14 占 8.09 GiB（`LinguisticData` 手工裁过，原版约 760 MB），Data14 使用一段时间后约 2.1 GiB（其中 MobileAsset 0.9 GiB）。刷回 iOS 12 后 SystemA 约 4.2 GiB。

**8.09 GiB 里有约 1.85 GiB 是写入方式造成的，第 94 轮之后已修复。** IPSW 系统镜像里 95% 的文件是 APFS 透明压缩（decmpfs）的：J96 14.8 有 18.7 万个，逻辑大小 3.8 GiB，实际只占 1.9 GiB，整个镜像在磁盘上占 5.75 GiB，解压后是 7.6 GiB。ramdisk 上的 GNU tar 1.17 不认识这种存法，以前写进去的都是解压后的文件。现在 `core/decmpfs.py` 和 `tools/n56-decmpfs.c` 会把镜像里的原始压缩数据原样写过去：类型 4（zlib，存在资源分支里）和类型 9（未压缩，存在属性里，不占数据块）。写完每个文件都会读回并核对 sha256。N66 镜像也只用了这两种类型，所以从 N66 部署的界面资源和配套文件同样保持压缩。在设备上实测 `System/Library/Frameworks`：612 MiB 降到 360 MiB，元数据完全一致，还更快（155 秒对 116 秒）。预计 System14 会从 8.1 GiB 降到 6.5 GiB 左右，以重刷后的实测为准。设置 `N56_DECMPFS=0` 可以退回纯 tar。

iOS 13 的 `rootfs.base_stream` 也改走同一个 `deploy_path`。13.7 的 J96 镜像在磁盘上占 4.6 GiB，解压后 6.3 GiB；其中类型 4 有 1.4 万个文件、逻辑 2.6 GiB，会保留压缩。另外 11.5 万个是类型 3（zlib 压缩后直接存在属性里），还没在设备上验证，暂时继续走 tar 解压写入，这部分合计约 450 MiB。要启用它，先在 ramdisk 上用 13.7 镜像里的类型 3 文件做一次写入、读回比对，通过后再把 3 加进 `core/decmpfs.py` 的 `VERIFIED_TYPES`。改动后的 iOS 13 也还没在设备上整机装过。

- 安装阶段写入 System14 前，先确认容器有足够余量：`umount` 后跑 `fsck_apfs -n -s /dev/disk0s1s4`，用总块数减去 “Total blocks allocated by spaceman”。删完文件立刻量的读数会偏大，要重新挂载、`sync` 后再量。
- 空间写满的典型症状：Setup 卡住反复重启、各守护进程报 `database or disk is full`、内核报 ENOSPC。不要误判成补丁问题。开机后 Siri 神经语音（约 470 MB）的下载会反复写满容器。
- 裁剪语言包、删除 iOS 12 内容之类的操作只做临时手工处理，不写进流水线。

## 构建

KC 顺序：J96 → KPloosh → SN2400 → Chestnut → N56 触摸 → B1 Wi-Fi → DRV2604 → D2186 PMU → CS42L67 → SEP 旧端点 → 旧 ANS 通信 → 显式卷选择 → checkra1n KPF + kerninfo。随后统一压缩、保留 watchtower 并签名。

离线构建可以显式指定卷号：

```sh
python3 n56patcher.py build --target n56-ios14 --system 4 --data 5 --workdir build/ios14-s4-s5
```

TrustCache 以 J96 静态 TC 为底，加入 launchd 任务缓存（主版本和不含配套的回退版本）、配套库、checkra1n binpack、Cydia 底包与 Cydia（只有 sha1 签名的那 154 个按 sha1 类型收录）、fairplayd.H2、bluetoothd/BlueTool、locationd，以及组合 dyld cache 的 cdhash。

## 源码结构

| 目录 | 职责 |
| --- | --- |
| `targets/n56_ios14.py` | 系统版本、IPSW、功能和独立卷配置 |
| `targets/_n56.py` | 共用设备和工具配置 |
| `patches/shared/` | 设备资源、移植算法、两个版本共用的补丁（含 `rootfs.cydia`） |
| `patches/ios14/` | 14.8 补丁、实现和 ABI 表 |
| `core/flow.py` | 共用构建、安装和启动阶段 |
| `core/installation.py` | 独立卷定位、挂载及布局记录 |

每个系统目录按 `kc/`、`dt/`、`rootfs/` 注册补丁，`impl/` 放实现和布局。注册表按目标加载 `shared` 和对应版本目录。CLI 和 GUI 使用同一套目标和功能选择。

## 关键适配

- **SEP / SKS**：N56 用 iOS 12 的 SEP 固件，它不上报端点表（discovery）。`kc.legacy_sep` 直接注册固定端点：SKS `0x12`；Logger、ART、ACM（`scrd`=10）用旧服务记录发布。媒体/文件密钥请求用 v0 格式。
- **SSE / 休眠**：`kc.legacy_sep` 发布 `sep-endpoint,sse`（端点 `0x0c`），AppleSSE 两侧缓冲区改为原生 `0x1000` 字节。原先缺少这项服务，`asd` 的 cryptogram 请求卡在内核服务等待中，`nfcd` 长期持有禁止休眠断言。
- **温控 / 休眠**：`rootfs.thermal_platform` 将原生 12 的 N56 温度模型、Objective-C 类和机型工厂分支内置到 14 的 `thermalmonitord`。温度采样、控制器与休眠判断使用原有框架。
- **面板 / 唤醒**：`kc.pinot_lcd` 移植同版本 N66 的 ApplePinotLCD，发布 `lcdE`，在休眠唤醒后恢复面板供电、复位和 DSI/DCS 初始化。
- **ANS**（功能 `ans`）：保留 N56 原 ANS 固件，RTBuddy 适配 `0xA` 握手和旧端点表。改用 J96 14.8 新固件的方案（原 `ans-new`）第 57 轮卡在 iBEC，已从项目删除，代码留档在本地 `research/ios14/archive/ans-new/`。
- **Touch ID**（功能 `touchid`）：14 的 GenericTransfer 和 13 的 AppleBiometricSEP 都只会新版分块协议，SEP 12 用的是邮箱直发加 `0x16` 子通道。`kc.touchid` 把 transact 和接收入口换成 `mesa_transport.c`，命令号、参数布局和通知号的转换在 `mesa_commands.h`。14 另外要发布 sbio 端点；13 的 Mesa 按编号直接取 endpoint，不需要。
- **NVRAM**：`dt.nvram` 按原机声明 8 KiB 的 `nvram-total-size`。
- **蓝牙**：bluetoothd 的机型和芯片组判定按“同一槽位的表项加 `mov/movk`”成对改写，借用 `BCM_4350C2` 组；同时部署 SystemA 的 BlueTool，提供 `BCM4345B0` 固件。
- **基带**：CommCenter 的 `getHardwareConfiguration` 不认识 N56（产品号 `0x11`），`rootfs.baseband_product` 把它归到 N69（`0x1b`），并改写 dyld cache 对应页的页哈希。`product-id` 不能改，否则 FairPlay 拒签，激活报 -42052。
- **运动**：`rootfs.motion_platform` 把 N56（枚举 0x34）放回受支持的分组，能力掩码 `0xa2be0781`（13.7 的值），三处代码分别在 locationd、CoreLocation、CoreMotion。修好以后 wifid ↔ locationd 不再成环，原来的 wifid 绕行补丁已删除。
- **界面资源**：`rootfs.ui_resources` 从 N66 补 iPhone 的 `.car`、键盘布局、启动苹果标等；`rootfs.wallpaper` 换成 iPhone 壁纸。
- **健康与手表**：`rootfs.companion` 从 N66 cache 派生 63 个库。为此补了合并同页数据段、small 方法列表和 Swift 相对指针重算、跨库尾跳等处理，还并入了 34 个配套守护进程。它会重写 launchd 缓存，必须和 `sep` 一起选。
- **越狱**：`kc.checkra1n` 在原始 KC 上离线运行 KPF 做特征匹配，合并进 N56 补丁，再写入 kerninfo shellcode（18H17 的 task 字段偏移是 `0x3f0/0x3f8`）。`rootfs.checkra1n_bootstrap` 部署 binpack、Loader 和 dropbear；`rootfs.cydia` 把 core bootstrap 和 Cydia 解包到 System14，首次开机时完成配置。
- **写入设备**：`Ramdisk.deploy_path` 和 `deploy_relative_paths` 把条目分成两路。目录、符号链接、未压缩文件走 tar（`-n --null -T` 显式清单）；类型 4/9 的压缩文件走 `n56-decmpfs`：它会建出空数据分支，写入资源分支和 decmpfs 头，设置 `UF_COMPRESSED`，再设属主、权限和时间，最后读回校验。iOS 12 内核会在写入时自动解压：已经压缩的文件被 `dd conv=notrunc` 原地改写或被 `cat >` 覆盖，结果都是正确的，所以现有的原地补丁不受影响。替换设备上已经执行过的程序时，要先删除再写入，直接覆盖会导致代码签名缓存失效，进程被 SIGKILL。
- **Data14**：`rootfs.finish` 在所有 overlay 之后，把 System14 的 `/private/var` 复制到 Data14（保留数字属主），所以 Cydia 包里的 `var/mobile` 条目也会带进去。不要在运行时直接往 Data14 解包，否则 `/var/mobile` 的属主会被改成 root，Cydia 配置时会报 Permission denied。
